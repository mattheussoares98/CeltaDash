# Master Feature Migration Checklist Template

> Copy or reference this checklist whenever migrating a single feature from the legacy structure to Feature-First + Riverpod.

---

## Target Feature: `[FEATURE_NAME]`

### Phase 1: Domain & Entities
- [ ] Create `lib/features/[feature]/domain/entities/[entity]_entity.dart` (pure Dart, immutable, `copyWith`, `const`).
- [ ] Create `lib/features/[feature]/domain/entities/entities.dart` (barrel file).
- [ ] Create `lib/features/[feature]/domain/repository/i_[feature]_repository.dart` (domain interface returning entities).
- [ ] Create `lib/features/[feature]/domain/repository/[feature]_repository_impl.dart` (implements interface, calls datasource, converts models via `.toEntity()`).
- [ ] Create `lib/features/[feature]/domain/repository/repository.dart` (barrel file).
- [ ] Create `lib/features/[feature]/domain/domain.dart` (layer barrel file).

### Phase 2: Data & Datasources
- [ ] Create `lib/features/[feature]/data/models/[model]_model.dart` (handles JSON parsing and `toEntity()`).
- [ ] Create `lib/features/[feature]/data/models/models.dart` (barrel file).
- [ ] Create `lib/features/[feature]/data/datasource/i_[feature]_datasource.dart` (datasource interface).
- [ ] Create `lib/features/[feature]/data/datasource/[feature]_datasource_impl.dart` (injects HTTP client, maps HTTP responses to models).
- [ ] Create `lib/features/[feature]/data/datasource/datasource.dart` (barrel file).
- [ ] Create `lib/features/[feature]/data/data.dart` (layer barrel file).

### Phase 3: Dependency Injection
- [ ] Create `lib/features/[feature]/providers.dart` declaring `@riverpod` providers for Datasource and Repository.
- [ ] Verify `providers.g.dart` is generated by the active build runner watcher.

### Phase 4: Presentation & Riverpod Controllers
- [ ] Create `lib/features/[feature]/presentation/controllers/[feature]_controller.dart` using `@riverpod` AsyncNotifier/Notifier.
- [ ] Create `lib/features/[feature]/presentation/controllers/controllers.dart` (barrel file).
- [ ] Migrate UI screen to `lib/features/[feature]/presentation/pages/[feature]_page.dart` using `ConsumerWidget`.
- [ ] Replace GetX Presenters, ViewModels, `Rx`, `Obx`, and `Get.find()` with `ref.watch()`, `ref.read()`, and `.select()`.
- [ ] Replace all GetX navigation (`Get.toNamed`, `Get.back()`, `Get.snackbar`) with GoRouter (`context.pushNamed`, `context.pop()`, `ScaffoldMessenger`).
- [ ] Register feature routes in `lib/routing/routes.dart` and `lib/routing/routes/[feature]/`.
- [ ] Extract UI subwidgets into `lib/features/[feature]/presentation/pages/components/` if the page file exceeds ~100 lines.
- [ ] Create `lib/features/[feature]/presentation/pages/pages.dart` and `components/components.dart` (barrel files).
- [ ] Create `lib/features/[feature]/presentation/presentation.dart` (layer barrel file).

### Phase 5: Automated Unit Tests
- [ ] Create `test/features/[feature]/data/datasource/[feature]_datasource_impl_test.dart` (mocking `IHttpClient`, verifying endpoint, parameters, response mapping & exceptions).
- [ ] Create `test/features/[feature]/domain/repository/[feature]_repository_impl_test.dart` (mocking `I[Feature]Datasource`, verifying entity mapping & error handling).
- [ ] Create `test/features/[feature]/presentation/controllers/[feature]_controller_test.dart` (using `ProviderContainer` to test async loading, data states, and mutations).

### Phase 6: Cleanup & Verification
- [ ] Create `lib/features/[feature]/[feature].dart` root feature barrel file.
- [ ] Remove all `import 'package:get/...';` from the feature.
- [ ] Verify all imports use `package:celta_dash/...` and point to barrel files (no relative imports).
- [ ] Verify no usecases or view models remain in the new feature.
- [ ] Verify that no legacy code references the old presenters for this migrated feature.
- [ ] Run automated tests for the feature and ensure all tests pass.
- [ ] Check for compile errors / analyzer warnings.
